## 2. Условие задачи
Предприятие выпускает изделия, состоящие из нескольких деталей. Для каждой детали задан технологический маршрут: последовательность операций на станках определённых типов. Готовые детали поступают в промежуточные накопители, после чего сборочный пост может начать работу только при наличии полного комплекта компонентов. 
После обработки деталь проходит контроль качества. Годная деталь передаётся дальше, бракованная направляется на повторную обработку или списывается. Вместимость накопителей ограничена, поэтому заполненный выходной буфер способен приостановить станок. Транспортные роботы перемещают детали между стадиями.
Требуется разработать консольное приложение, моделирующее сборочную линию.

## Входные параметры 
•	перечень изделий и состав комплектов;
•	технологические маршруты деталей;
•	количество станков и сборочных постов;
•	число транспортных роботов; 
•	длительность операций; 
•	вместимость накопителей; 
•	вероятность брака и правила повторной обработки; 
•	план выпуска изделий.

## Отображаемые события 
Необходимо отображать создание детали, постановку в очередь, начало и окончание операции, контроль качества, обнаружение брака, повторную обработку, перемещение, поступление в комплект, начало сборки и выпуск изделия.

## Инварианты 
•	станок обрабатывает не более одной детали; 
•	деталь находится на одной стадии или у одного транспортного робота;
•	операция выполняется после всех предыдущих операций маршрута; 
•	забракованная деталь не входит в готовое изделие; 
•	сборка начинается только при наличии полного допустимого комплекта.

## Завершение
Программа завершается после выполнения плана, исчерпания исходных деталей либо признания дальнейшего производства невозможным. Станки, контролёры, сборочные посты, транспортные роботы и детали являются самостоятельными участниками модели.

## Сценарий

Сборочная линия моделируется как система из 14 процессов: одного главного процесса и 13 работников. Дополнительно сервер использует поток для приёма TCP-подключений клиентов.

**Соответствие сущностей программы процессам:**

- *Фабрика* - главный процесс (`process.c`). Создаёт детали, управляет очередями, станками, контролёрами, роботами и сборочными постами.
- *Работники* - 13 отдельных процессов (`worker.c`): пять станков, три контролёра, три робота и два сборочных поста.
- *Деталь* - запись в массиве `parts`. Её состояние изменяется главным процессом.
- *Клиенты* - отдельные экземпляры `client.c`, которые подключаются к серверу и получают события производства.

**Взаимодействие фабрики и работников:**

1. Фабрика назначает работнику задание (`link_send_job`).
2. Работник выполняет его заданное время.
3. После завершения работник сообщает об этом фабрике (`link_report_done`).
4. Фабрика получает результат (`link_wait_done`), обновляет состояние детали и запускает следующие доступные операции.

Работники не управляют производством самостоятельно. Все решения принимает фабрика. Связь между ними организована через интерфейс `Link` (`link.h`).

**Взаимодействие сервера и клиентов:**

1. Сервер запускает TCP-сервер наблюдения (`observer_start`).
2. Клиент подключается по IP-адресу и порту.
3. Сервер отправляет клиенту последние сохранённые события.
4. Новые события передаются всем подключённым клиентам.
5. При отключении клиента производство продолжается. Клиент может подключиться повторно.
6. Если все 32 места заняты, новый клиент получает сообщение `SERVER_BUSY` и отключается.

Сервер поддерживает до 32 клиентов и хранит последние 300 событий. Клиент, который не читает данные, отключается сервером и не тормозит моделирование.

## Пользовательский интерфейс

Ввод во время работы не требуется. Параметры производства задаются в `params.h`:

- план выпуска - 5 изделий;
- количество типов деталей - 3;
- станков - 5;
- контролёров - 3;
- роботов - 3;
- сборочных постов - 2;
- вместимость накопителя - 4 детали;
- вероятность брака - 0.2;
- вероятность переделки - 0.7.

Пользовательский интерфейс состоит из двух программ:

- `server` - запускает производство и сервер наблюдения;
- `client` - подключается к серверу и отображает события.

**Сборка:**

```sh
gcc -Wall -Wextra -o server server.c process.c link.c worker.c observer.c event.c queue.c -lpthread
gcc -Wall -Wextra -o client client.c
```

**Запуск сервера:**

```sh
./server -a 0.0.0.0 -p 5000 [-d 100]
```

Необязательный параметр `-d` задаёт, сколько реальных миллисекунд длится одна единица модельного времени (по умолчанию 100).

**Запуск клиента:**

```sh
./client -a 127.0.0.1 -p 5000
```

Для подключения дополнительных наблюдателей запускаются другие экземпляры клиента с теми же параметрами.

В журнал выводятся события (в начале каждой строки - модельное время):

- `part N created` - создание детали;
- `part N waits robot` - деталь ждёт свободного робота;
- `robot R takes part N` - робот забрал деталь;
- `part N -> machine K` / `part N -> inspector K` - деталь доставлена в очередь станка или контролёра;
- `machine K starts part N` - начало обработки;
- `machine K ends part N` - завершение обработки;
- `inspector K checks part N` - проверка детали;
- `part N ok` / `part N bad` - результат контроля;
- `part N in buffer T` - годная деталь положена в накопитель;
- `inspector K blocked` / `inspector K unblocked` - накопитель полон, контролёр ждёт место;
- `part N rework` - отправка на переделку;
- `part N scrapped` - списание брака;
- `assembly A starts product P` - начало сборки;
- `product P done` - завершение сборки изделия.

В конце сервер выводит статистику: время работы, количество выпущенных изделий, число событий и состояние деталей.

## Запуск и завершение

**Запуск:**

- Сервер запускается отдельно и самостоятельно создаёт процессы работников.
- Клиенты запускаются отдельно и подключаются к серверу по TCP.
- Сервер и клиенты могут работать на одном компьютере или на разных компьютерах в сети.
- Для подключения с другого компьютера вместо `127.0.0.1` указывается IP-адрес сервера.

**Завершение:**

- *План выполнен* - сервер останавливает работников, выводит статистику, отправляет клиентам `SERVER_STOP` и завершает работу.
- *Достигнут лимит модельного времени* - производство останавливается, выводится итоговая статистика.
- *Производство невозможно продолжить* - сервер завершает моделирование.
- *Ctrl+C на сервере* - сервер останавливает работников и уведомляет клиентов сообщением `SERVER_STOP`.
- *Ctrl+C на клиенте* - отключается только этот клиент, производство продолжается.
- *Отключение клиента* - остальные клиенты и сервер продолжают работу.
- *Повторное подключение* - клиент получает сохранённую историю событий и продолжает наблюдение.

Код возврата сервера: 0 - план выполнен, 2 - план не выполнен, 1 - ошибка запуска.
